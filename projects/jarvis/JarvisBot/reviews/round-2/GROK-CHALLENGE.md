### GROK-5 · The DeepSeek tool-calling gap cites the redirected guide and misses the resume rule

- **Severity:** major
- **Finding:** DEEPSEEK-6, and my own `GROK.md` label, treat DeepSeek tool use as undocumented because `https://api-docs.deepseek.com/guides/function_calling` renders the first-call page. The sitemap lists `https://api-docs.deepseek.com/guides/tool_calls`. That page documents an OpenAI-SDK tool round trip for `deepseek-flash` and states that Chat Completions cannot insert tool calls mid-conversation, while the Anthropic Messages API and the Responses API can. Akeru's DeepSeek path is a Custom API preset of unverified wire format. DeepSeek's own Claude Code and Codex pages are API-key harness routes onto the Anthropic and Responses shapes. Calling 3 and 4 equally blocked, or calling the capability undocumented, hides the format constraint that decides whether a resumed tool transcript is even in contract.
- **Proposed correction:** Cite the tool-calls guide. Record the base URL and API family in the continuity spike. Treat a Chat Completions preset that cannot replay a tool call as a resume gap. Treat G7's harness configs as API-key routes, separate from Claude and ChatGPT subscriptions. Do not claim a successful live tool loop; none was sent.
- **Evidence:** G6 and G7, fetched 2026-10-24. DEEPSEEK-6's cited URL. No API request was submitted.
- **Confidence:** high that the tool-calls page says this; medium that Akeru's preset uses Chat Completions; unknown whether a live tool call succeeds.

### GROK-6 · Delegated-result delivery is being counted as safe resume of external work

- **Severity:** major
- **Finding:** Option 3's collaboration advantage is described, in DEEPSEEK's proposal, as exactly-once delegated-result delivery. Akeru's chat guide gives the requesting bot the result once, and the same guide says a server restart stops running delegated work and **Try again** sends the task again as a new card. CHATGPT's matrix and tests already require reconciling an uncertain external write. The proposals still leave "exactly-once" in the asset column for option 3. A second submission of a phone call, WhatsApp send, or calendar write is the failure the primary goal names. The card does not record that the external system accepted the first attempt.
- **Proposed correction:** Split the two guarantees in the comparison. Keep exactly-once chat delivery as a documented Akeru behavior. Mark external-write resume as custom on option 3 until a stub ledger survives restart and **Try again**. Apply the same ledger to options 1, 2, and 4. Do not run the restart against a live connector.
- **Evidence:** G5, [Akeru chats](https://raw.githubusercontent.com/opencoredev/akeru-bot/main/docs/user/chats.md), fetched 2026-10-24. DEEPSEEK.md "exactly-once delegated-result delivery."
