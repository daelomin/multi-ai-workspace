# 06 — UX flows and wireframes

**Status:** draft v0.3 · **Normative:** `spec.md` §4, §16 · **Visual reference:** HUMAN's Grokbot screenshot (roster, rooms, conversation, shared results).

The workspace is a work surface, not a dashboard. Indicators are compact and expand on
demand. Every wireframe below is a structural sketch, not a visual design.

---

│ ▸ Technical  │  │ Sarah · 2m                             │  │  Gmail (read)      │
│   Board      │  │ Challenge: sample is not independent.   │  │  Sheets (write)    │

```

Key rules: one primary column; room context stays visible; the inspector is contextual
(bot, task, rating or proposal) and collapsible. Status markers are text-first (colour is
secondary) and respect reduced motion.

│                        Marketing · Counsel · Ops · Observer  │
│                                                              │
│ Template match: "Data analyst (evidence-first)"  [ change ]  │

└──────────────────────────────────────────────────────────────┘

Step 2 — Identity            Step 3 — Policy             Step 4 — Dependencies
 name  [ Natalia        ]     route  (•) balanced         ✗ Gmail not connected

Behaviour: each step is resumable; the persona preview shows template defaults vs
instance edits; dependency failures link to the fix and never silently disable a chosen
capability. "Start with a task" proposes one concrete first task with acceptance
criteria derived from the role and the room's board.

## 4. Route / model switch

```
Switch route for Natalia                               scope: [ bot ▾ ]
┌────────────────────────────────────────────────────────────────────┐
│ current  claude/sonnet-4.7 · Max 20x · skills native ✓             │
│                                                                    │
│ ○ codex/gpt-5.1-codex     floor ✓   +speed  −skill parity (1 gap)  │
│ ● deepseek/deepseek-chat  floor ✓   −cost   skills: injected ⚠     │
│ ○ grok/grok-4.7           floor ✓   +context skills native ✓       │
│ ○ claude/opus-5.1         floor ✓✓  +judgment  +cost               │
│                                                                    │
│ Effects: next task uses this route. Current task T-142 keeps its   │
│ route unless you also switch the task. Persona, memory and skills  │
│ stay attached to Natalia.                                          │
│                                                                    │
│ [ cancel ]                         [ switch bot ]  [ also task ]   │
└────────────────────────────────────────────────────────────────────┘
```

Every switch shows: floor status, known gaps, skill support level, relative cost/speed,
and the exact scope of the change. A quota-blocked route shows the reset time and the
failure class, not a generic "unavailable".

## 5. Triage before a costly task

```
Before we start — this looks like a large task
┌─────────────────────────────────────────────────────────────────────┐
│ "Integrate WhatsApp Business templates and sender registration"     │
│ complexity  ambiguity ●●●○○  integrations ●●●●○  validation ●●●○○  │
│ estimate    6–11 h · $4–$9 · confidence 0.4  (basis: 2 similar)    │
│ readiness   not-ready — missing: template approval policy, sandbox  │
│ proposed    (1) discovery 45 min, then re-triage                    │
│             (2) advanced model now (est. +40%)                      │
│             (3) split: spec by advanced, build by cheap             │
│ [ discovery ]  [ start with advanced ]  [ split ]  [ edit scope ]   │
└─────────────────────────────────────────────────────────────────────┘
```

Discovery has a visible budget and stopping rule. "Not ready" disables the cheap-build
option until the named gaps are assigned. Estimates are ranges with confidence; the
actual is compared on completion.

┌──────────────────────────────────────────────────────────────────────────────┐
│ total  $41.20 estimated · 12.4M tokens · 3 accounts · coverage 94%           │
│        (6% unknown: grok usage not reported)                                │
├──────────────────────────────────────────────────────────────────────────────┤

│ by route      claude $21.3 (subscription-equivalent) · deepseek $6.8 (API)   │

```

Each number carries its measurement class; clicking a row opens the records. "Unknown"
is a coverage figure, not a zero. Subscription-equivalent and API spend are never summed
into one misleading "bill".

## 8. Recovery

```
T-142 is paused — provider quota exhausted
┌─────────────────────────────────────────────────────────────────────┐
│ claude account "Max 20x" hit its usage limit · resets in 3h 12m      │
│ checkpoint chk_01f… saved · nothing was half-published              │
│ options:  (1) wait          (2) switch to an adequate route          │
│           (3) switch account (backup 1, verified)                    │
│           (4) stop and hand off                                      │
│ [ resume on deepseek ]   [ wait ]   [ switch account ]   [ cancel ]  │
└─────────────────────────────────────────────────────────────────────┘

ACTION a-88 · mail.send · state: unknown
  the provider may have accepted the message (no acknowledgement)
  [ check sent folder ]  [ mark as sent ]  [ retry (new action) ]
  dependent work is blocked until this is resolved
```

The recovery surface never offers "retry" for an `unknown` external action without a
reconciliation step. Cancel is always available and always keeps state.

## 9. Observer proposals

```
OBSERVER PROPOSAL p-12 · awaiting review
target  procedure "weekly-scorecard" v3
change  add an explicit evidence check before publishing scores
why     3 of 5 ratings cited "scores without links"; rework 22%
eval    shadow run on 6 historical tasks: acceptance 4/6 vs 3/6 baseline,
        cost +$0.34/task, no regression on speed
cost    observer $1.20 to evaluate
[ view diff ]  [ approve & activate ]  [ reject with reason ]  [ ask for more evidence ]
```

Activation is separate from evaluation, creates a new version and a rollback point, and
cannot touch goals or persona identity fields (those show as "requires human edit").

│        Administration board   (membership from names only)                  │
│ routine: Weekly bot scorecard → procedure DRAFT · schedule: Monday 09:00    │

Nothing is presented as the original bot's instructions. Drafts are editable; the
checklist remains until filled or explicitly waived by a HUMAN.
